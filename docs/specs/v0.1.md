# Judge v0.1 specification

[Back to README](../../README.md)

## Status and normative language

This document defines the intended Judge v0.1 contract. Judge is pre-release;
the specification is normative even where implementation does not yet exist.

The words **MUST**, **MUST NOT**, **SHOULD**, **SHOULD NOT**, and **MAY** describe
requirements as defined by RFC 2119-style usage.

## Scope

Judge turns constrained probabilistic decisions into typed TypeScript control
flow. The provider selects a Boolean, choice, or score outcome. Judge validates
the outcome, applies confidence policy, and either returns the decision or
executes exactly one application callback.

Jev is the default provider in v0.1. Core semantics remain provider-independent
and are defined in the [core specification](core.md).

## Package entry points

Judge is one ESM-only package with `"sideEffects": false`.

| Entry point | Responsibility |
| --- | --- |
| `@brkn-labs/judge` | Default Jev client with direct TypeSafe or gateway transport |
| `@brkn-labs/judge/core` | Provider-neutral client and public core types |
| `@brkn-labs/judge/mock` | Deterministic test provider |
| `@brkn-labs/judge/gateway/vercel` | Vercel AI Gateway transport |
| `@brkn-labs/judge/gateway/cloudflare` | Cloudflare transport |
| `@brkn-labs/judge/gateway/openrouter` | OpenRouter transport |

The root factory MUST accept exactly one explicit Jev transport:

```ts
import { createJudge } from "@brkn-labs/judge";

const direct = createJudge({
  apiKey: process.env.TYPESAFE_API_KEY!,
});

const routed = createJudge({
  gateway: vercelGateway({
    apiKey: process.env.AI_GATEWAY_API_KEY!,
  }),
});
```

Judge MUST NOT silently read credentials or select a gateway. The `/core`
factory requires an explicit `DecisionProvider`:

```ts
import { createJudge } from "@brkn-labs/judge/core";

const judge = createJudge({ provider });
```

## Public API

The v0.1 client surface is:

```ts
createJudge(options);

judge.if(options);
judge.switch(options);

judge.boolean(options);
judge.choice(options);
judge.score(options);

judge.condition<T>(condition);
judge.choiceQuestion<T>()(criteria);
judge.preset(definition);

judge.withContext(context);
judge.scope<T>();
```

`if()` and `switch()` are control-flow wrappers. `boolean()`, `choice()`, and
`score()` return normalized decisions and MUST NOT execute application
callbacks. `score()` is experimental in v0.1; its public contract may evolve
before v1 without weakening Boolean or Choice compatibility.

## Required execution guarantees

For every `if()` or `switch()` invocation:

1. Judge MUST validate local configuration before provider evaluation.
2. Judge MUST resolve and serialize context before provider evaluation.
3. Judge MUST treat the provider response as untrusted data.
4. Judge MUST validate the response before any application callback runs.
5. Judge MUST apply confidence policy before selecting a callback.
6. Judge MUST re-check cancellation immediately before callback execution.
7. Judge MUST execute exactly one normal or uncertainty callback.
8. Judge MUST return the awaited result of that callback.

Judge MUST NOT speculatively execute callbacks, execute several callbacks for
comparison, or run a normal branch after an evaluation failure. Exceptions
thrown by an application callback pass through unchanged.

## Confidence and uncertainty

Confidence thresholds are finite numbers in `[0, 1]`. Invalid thresholds cause
`ConfigurationError` before context resolution or provider evaluation.

When `decision.confidence >= minimum`, Judge executes the selected normal
branch. Otherwise it executes the configured `uncertain` callback. Equality is
accepted.

Without a confidence policy, Judge executes the valid provider-selected branch
regardless of confidence. A reusable preset MAY provide a default minimum, but
an invocation using that threshold MUST provide a resolvable uncertainty
callback. A threshold with no uncertainty callback is a `ConfigurationError`.

Core MUST NOT invent a margin, entropy, or calibration interpretation. Provider
confidence is normalized but remains provider-defined.

## Context

Context contains structured facts. A condition or question contains the
judgment to make about those facts. Judge MUST NOT require applications to
concatenate structured facts into instructions.

Effective context uses this precedence, from least to most local:

```text
global < scoped < preset.getContext(input) < invocation
```

Judge deep-merges plain objects, replaces arrays, and treats `undefined` as an
absent override. Preset context is resolved exactly once per evaluation and is
not cached unless caching is explicitly configured.

Only resolved context is sent to a provider. Preset `input` is application data
for context resolution and MUST NOT be sent automatically.

## Providers and transports

A `DecisionProvider` implements normalized Boolean, Choice, and Score decisions.
Providers own protocol mapping and response validation; they MUST NOT own
confidence routing or callback execution.

The default [Jev provider](provider-jev.md) supports a direct TypeSafe API key
or an explicit [gateway plugin](gateway-plugins.md). Both paths MUST normalize
equivalent upstream decisions to the same core shapes.

The direct path MUST use Node's built-in `fetch` against TypeSafe's documented
System One HTTP endpoint and MUST NOT depend on `@typesafe-ai/sdk`. Judge maps
its internal Boolean primitive to TypeSafe `noul` and normalizes TypeSafe's
numeric Score response to the core Score shape.

The deterministic mock provider is mandatory. Unit tests MUST be able to cover
all branches without network access, credentials, or probabilistic fixtures.

## Errors

Core exports stable error classes:

- `ConfigurationError` — invalid local options, thresholds, or case maps.
- `SerializationError` — context cannot be represented by the provider contract.
- `ProviderError` — authentication, transport, rate-limit, timeout, or remote execution failure.
- `ProviderContractError` — malformed or impossible provider output.
- `AbortError` — evaluation was cancelled.

Judge MUST NOT convert application callback exceptions into these error types.
Evaluation errors MUST NOT fall through to normal branches unless a future,
explicit fallback policy defines that behavior.

## Observability

`createJudge()` MAY accept `onDecision` and `onError` hooks. Decision events
contain stable evaluation metadata such as invocation ID, kind, selected
outcome, confidence, duration, provider, gateway, model, and normalized usage.

Full context and raw provider output MUST be excluded by default. Explicit
debug capture MUST be opt-in and documented as sensitive.

An observability hook failure MUST NOT alter branch selection, execute another
branch, or replace an application callback result. Judge SHOULD report such a
failure through `onError` when configured.

## Runtime safety

- Every evaluation API MUST accept `AbortSignal`.
- Context resolution and transport MUST receive the same signal.
- Judge MUST check cancellation before context resolution, before provider
  evaluation, and immediately before callback execution.
- Provider timeouts MUST be configurable.
- Retries MUST be opt-in.
- Raw provider data MAY be exposed behind an optional `raw` field.
- Context caching MUST be opt-in and belong to context resolution, not gateways.

Remote cancellation cannot guarantee that an upstream service did no work. It
does guarantee that Judge will not begin an application callback after locally
observing cancellation.

## Tree-shaking requirements

Complete tree-shaking is a release requirement:

- The package MUST be side-effect-free ESM.
- The root MAY include the default Jev adapter and direct TypeSafe transport.
- The root MUST NOT include optional gateways, the mock, or non-Jev providers.
- `/core` MUST have no dependency path to Jev, TypeSafe, mock, or gateways.
- Each integration MUST be an independent subpath entry.
- Importing one integration MUST NOT load sibling integrations.
- There MUST be no import-time registration or global plugin registry.

The [bundle boundary](../architecture/decision-lifecycle.md) is verified by
release fixtures rather than inferred from source layout alone.

## Acceptance criteria

Judge v0.1 is accepted when automated tests prove:

- `if()` executes the correct `then`, `else`, and `uncertain` callbacks.
- `switch()` derives legal outcomes from literal case keys.
- Return types are awaited unions of every possible callback result.
- Impossible choices and malformed decisions execute no callback.
- Context merges as `global < scoped < getContext(input) < invocation`.
- Confidence equality passes because acceptance uses `>=`.
- Cancellation prevents callback execution, including after provider resolution.
- Mock-provider unit tests need no remote credentials.
- Direct TypeSafe and gateway Jev paths normalize to identical core decisions.
- Direct Boolean requests use TypeSafe `noul`, and direct Score responses retain
  the numeric weighted score and ordered level probabilities.
- The direct transport has no TypeSafe SDK dependency, bounds response bodies,
  and performs no retry unless one is explicitly configured.
- Provider-specific code does not appear in the `/core` module graph.
- A `/core` bundle contains no Jev, direct TypeSafe transport, mock, or gateway
  code.
- Each optional integration is absent unless its exact subpath is imported.
- Importing one gateway includes no sibling gateway or mock code.
- Provider failures use stable error classes rather than vendor exceptions.
- Full context is absent from default observability events.

## Deferred features

The following are outside v0.1:

- runtime schemas through Standard Schema or Zod;
- reference retrieval and context compression;
- calibration tools and recorded decision datasets;
- batch or multi-question evaluation;
- margin, entropy, per-case, and application-predicate confidence policies;
- OpenTelemetry integration;
- local and open-model providers;
- workflow-engine and agent-runtime adapters.

See the [roadmap](../roadmap.md) for non-committed future directions.
